# 知识库平台部署与配置手册

## 运行环境要求

| 项目 | 最低要求 | 推荐 |
| --- | --- | --- |
| Python | 3.11 | 3.12 |
| 内存 | 2 GB | 8 GB |
| 磁盘 | 5 GB（含向量与索引） | 50 GB SSD |
| 操作系统 | Linux / macOS / Windows | Linux x86_64 |

本平台的核心检索链路**不依赖任何第三方 Python 包**，只用标准库；`numpy` 若存在会自动
用于向量检索加速，`python-docx`、`openpyxl`、`pypdf` 分别用于解析 Word、Excel、PDF。
缺少这些包时，对应格式会被跳过并在入库报告中标记，不影响其他格式。

## 环境变量

所有配置以 `RAGKB_` 为前缀，支持 `.env` 文件（进程环境变量优先）：

```bash
# 存储
RAGKB_DATA_DIR=./data
RAGKB_DB_PATH=./data/ragkb.sqlite3

# Embedding：hashing 为本地词法兜底，openai 为任意 OpenAI 兼容网关
RAGKB_EMBED_PROVIDER=openai
RAGKB_EMBED_MODEL=BAAI/bge-m3
RAGKB_EMBED_BASE_URL=https://api.siliconflow.cn/v1
RAGKB_EMBED_API_KEY=sk-xxx
RAGKB_EMBED_DIM=1024

# 生成模型
RAGKB_LLM_PROVIDER=openai
RAGKB_LLM_MODEL=deepseek-chat
RAGKB_LLM_BASE_URL=https://api.deepseek.com/v1
RAGKB_LLM_API_KEY=sk-xxx
RAGKB_LLM_MAX_TOKENS=900

# 重排：none / lexical / http
RAGKB_RERANK_PROVIDER=http
RAGKB_RERANK_MODEL=BAAI/bge-reranker-v2-m3
RAGKB_RERANK_BASE_URL=https://api.siliconflow.cn/v1

# 检索参数
RAGKB_CHUNK_SIZE=800
RAGKB_CHUNK_OVERLAP=120
RAGKB_RETRIEVE_CANDIDATES=50
RAGKB_FUSE_TOP_K=20
RAGKB_FINAL_TOP_K=6

# 服务
RAGKB_API_HOST=0.0.0.0
RAGKB_API_PORT=8000
RAGKB_API_KEY=change-me
```

**注意**：更换 embedding 模型后必须重新入库（`ingest --force`），否则新旧向量
不在同一向量空间，检索结果会明显变差。平台会在启动时检查并告警。

## 启动与验证

```bash
# 1) 入库（增量，重复执行会自动跳过未变更文件）
python -m ragkb.cli ingest ./data/corpus --acl public

# 2) 冒烟验证
python -m ragkb.cli ask "如何申请备用金？"

# 3) 启动 HTTP 服务（内置 Web UI）
python -m ragkb.cli serve --host 0.0.0.0 --port 8000

# 4) 健康检查
curl http://127.0.0.1:8000/health
```

端口冲突时修改 `RAGKB_API_PORT` 即可。服务为单进程多线程模型，
默认监听 `127.0.0.1`；对外暴露请务必设置 `RAGKB_API_KEY` 并置于反向代理之后。

## 目录结构

```
data/
  ragkb.sqlite3      # 文档、切块、倒排索引、向量、权限
  traces.jsonl       # 每次问答的结构化 trace
  feedback.jsonl     # 用户反馈
  corpus/            # 原始语料（只读输入）
```

备份只需复制 `ragkb.sqlite3`（WAL 模式下请先执行 `PRAGMA wal_checkpoint(TRUNCATE)`
或停服后复制，避免丢失未落盘的事务）。

## 性能与容量

单机 SQLite 版本在 **10 万 chunk** 规模内表现稳定：BM25 检索 p95 < 30 ms，
向量暴力检索 512 维 10 万条 p95 < 80 ms（numpy 加速）。超过该规模建议：
把向量通道换成 Milvus/Qdrant，词法通道换成 OpenSearch，本项目的
`vector_search` / `lexical_search` 两个方法即为替换点。

召回率优化建议按顺序做：① 先补数据（很多"检索不准"其实是语料缺失）；
② 打开 rerank；③ 调 `chunk_size`（技术文档建议 600–900，制度类建议 800–1200）；
④ 最后才考虑换 embedding 模型。

## 常见故障排查

**检索结果为空**
先确认 ACL：默认只检索 `public` 标签的文档，用 `--acl internal` 入库的内容
需要请求头带对应角色。其次检查 `RAGKB_RETRIEVE_CANDIDATES` 是否被误设为 0。

**回答总是拒答**
检查 `RAGKB_REFUSE_SCORE_FLOOR`，默认 0.02 偏低不该误拒。更常见的原因是
入库时用了 hashing 兜底向量、而查询时切到了线上模型，导致向量空间不一致。

**上传 413 错误**
单个文件默认上限 20 MB，由 `RAGKB_MAX_UPLOAD_MB` 控制。超大 PDF 建议先拆分。
